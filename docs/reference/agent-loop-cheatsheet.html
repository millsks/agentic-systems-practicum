Agent Loop Cheat Sheet

The request and response shapes, stop reasons, tool rules, and the loop itself on one page. Every snippet uses agentlab; for the real API, create the client with anthropic.Anthropic() and change nothing else.

Request shape

response = client.messages.create(
    model="claude-opus-5-5",           # al.MODEL; also claude-sonnet-5-5, claude-haiku-5-5 (no date suffix)
    max_tokens=1024,                   # required; output cap (up to 128K; large values need streaming)
    system="You are a concise research assistant.",   # optional; instructions, not a message
    messages=[                         # required; the full history, every request (the API is stateless)
        {"role": "user", "content": "What's the weather in Paris?"},
    ],
    tools=TOOLS,                       # optional; list of tool definitions
    output_config={"effort": "medium"},   # optional; low | medium (default) | high | xhigh | max
    stop_sequences=["END"],            # optional
)

BlockWho sends itFields

Check stop_reason before reading content. Append response.content (the blocks, not just the text) to keep tool_use blocks in the history.

stop_reason: what to do

stop_reasonMeansDo this
end_turnThe model finished.Return the text. The loop ends.
tool_useThe model wants tool calls.Append the assistant turn, run every tool_use, send all results in one user message, loop.
max_tokensOutput hit max_tokens; content is cut off.Raise max_tokens, ask for shorter output, or stop and report. Never treat as complete. A cut-off tool_use must not be run.
stop_sequenceA stop sequence matched; stop_sequence says which.Use the text up to that point.
pause_turnA server tool paused a long turn.Append the assistant turn and send the request again to continue.
refusalThe model declined.Read stop_details (category, explanation); stop and report. Do not retry the same request.

Tool definition

TOOLS = [{
    "name": "get_weather",                       # ^[a-zA-Z0-9_-]{1,64}$, unique
    "description": "Current weather for one city. Use when the user asks about weather now. "
                   "Returns 'temp C, conditions'. Read-only.",
    "strict": True,                              # optional: guarantees schema-valid input
    "input_schema": {
        "type": "object",                        # always an object
        "properties": {
            "city": {"type": "string", "description": "City name, e.g. 'Paris'."},
            "unit": {"type": "string", "enum": ["c", "f"], "description": "Temperature unit."},
        },
        "required": ["city"],                    # strict needs required ...
        "additionalProperties": False,           # ... and additionalProperties: false
    },
}]
  • The model sees only name, description, and input_schema; it never runs code. Say when to use the tool and what it returns (M07, M12).
  • tool_choice defaults to auto; {"type": "none"} disables tools. Forcing a call is rejected on Opus 5.5: steer with the prompt.

tool_use / tool_result pairing rules

messages.append({"role": "assistant", "content": response.content})    # 1. the whole assistant turn
messages.append({"role": "user", "content": [                            # 2. the very next message
    {"type": "tool_result", "tool_use_id": "toolu_A", "content": "18 C, sunny"},
    {"type": "tool_result", "tool_use_id": "toolu_B", "content": "No city named 'Pariss'.", "is_error": True},
]})
  1. Every tool_use gets exactly one tool_result with the same id as tool_use_id.
  2. The results go in the next message, which is a user message.
  3. Parallel calls (several tool_use blocks in one response): return all results in one user message, not one message per result.
  4. tool_result blocks come first in that message; any text goes after them.
  5. Never answer a tool_use that is not in the previous assistant message.
  6. A failed tool still gets a result: "is_error": True and a message that says what went wrong and how to recover (M10). Never drop it.

The minimal loop

def run_agent(client, task, tools, impls, max_steps=10):
    messages = [{"role": "user", "content": task}]
    for _ in range(max_steps):
        response = client.messages.create(model=al.MODEL, max_tokens=1024, tools=tools, messages=messages)
        messages.append({"role": "assistant", "content": response.content})
        if response.stop_reason != "tool_use":
            return response, messages                     # end_turn, max_tokens, refusal, ...: caller decides
        results = []
        for block in response.content:
            if block.type != "tool_use":
                continue
            try:
                output = impls[block.name](**block.input)
                results.append({"type": "tool_result", "tool_use_id": block.id, "content": str(output)})
            except Exception as exc:                      # unknown tool, bad input, tool failure
                results.append({"type": "tool_result", "tool_use_id": block.id,
                                "content": f"{type(exc).__name__}: {exc}", "is_error": True})
        messages.append({"role": "user", "content": results})   # all results, one message
    raise RuntimeError(f"stopped after {max_steps} steps")

Run it with a parallel call (two tool_use blocks in one response) and a failing tool. Two script steps, two requests.

Common BadRequestErrors and fixes

Error message (agentlab wording)CauseFix
tool_use ids were found without tool_result blocks immediately after: toolu_...A tool_use was not answered in the next message, or one of several parallel calls was skipped, or results were split across messages.Answer every id, all in the one user message right after the assistant turn.
tool_result references unknown tool_use id ...Wrong or made-up tool_use_id.Copy block.id exactly.
tool_result blocks must answer tool_use blocks in the previous assistant messageThe assistant turn was never appended, or only its text was appended.Append response.content before the results.
tool_result blocks must come before any other contentText placed before the results.Put tool_result blocks first.
the final message must not be an assistant messagePrefill, or a loop that sent the history right after appending the assistant turn.End with a user message.

text content blocks must be non-emptyAn empty string as content or in a text block.Skip empty text; send a real message.

A BadRequestError (400) never succeeds on retry: fix the request. Retry only RateLimitError (429), InternalServerError (5xx), and APIConnectionError, with backoff.

Budget guards

PRICE_IN, PRICE_OUT = 4 / 1_000_000, 20 / 1_000_000    # Opus 5.5: $4 / $20 per million tokens
start, tokens, cost, seen = time.monotonic(), 0, 0.0, set()
for step in range(MAX_STEPS):                            # 1. step limit
    response = client.messages.create(...)
    tokens += response.usage.input_tokens + response.usage.output_tokens
    cost += response.usage.input_tokens * PRICE_IN + response.usage.output_tokens * PRICE_OUT
    if tokens > MAX_TOKENS: return report("token_budget")      # 2. token budget
    if cost > MAX_COST: return report("cost_budget")           # 3. cost budget
    if time.monotonic() - start > MAX_SECONDS: return report("time_limit")   # 4. wall clock
    for block in tool_uses(response):
        key = (block.name, json.dumps(block.input, sort_keys=True))
        if key in seen: return report("repeated_call")         # 5. loop detection
        seen.add(key)
    ...
return report("max_steps")
  • Always stop with a structured result: answer (if any), steps, tokens, cost, and the reason stopped (M11).
  • Input tokens grow every step, because the whole history is re-sent. Check budgets after every response.
  • Prices per million tokens (input/output): Opus 5.5 $4/$20, Sonnet 5.5 $2/$10, Haiku 5.5 $0.10/$0.50.
