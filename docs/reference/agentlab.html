agentlab Reference

agentlab is the practicum's teaching library: a scripted, offline stand-in for the Anthropic Python SDK's Messages API, plus a few helpers for reading transcripts, validating JSON, and estimating tokens. Every runnable cell and exercise in the course uses it. This page documents every public name and how each one maps to the real SDK.

MockClient

al.MockClient(script=None, *, responder=None, seed=0)

A client with the same messages surface as anthropic.Anthropic(). Each request is first validated like the real API, recorded in client.requests, then answered by the next script step.

Parameter / attributeMeaning
scriptList of steps, consumed one per request, in order.
responderA function Request -> step used for every request once the script is empty. Without it, an empty script raises MockScriptError.
seedSeeds the client's random.Random, shared with one_of and with function steps through request.rng. Same seed, same choices.
client.requestsEvery validated Request, in order. Requests that fail validation are not recorded and do not consume a step.
client.remainingNumber of script steps not yet used.
client.messagesThe Messages resource: create, stream, count_tokens.

messages.create(**kwargs)

Accepted keyword arguments: model and max_tokens (required), messages, system, tools, tool_choice, stop_sequences, output_config, thinking, metadata, cache_control, stream. Returns a Message. With stream=True it returns an iterator of StreamEvents instead.

After choosing a step, the mock finishes the response in this order:

  1. Gives every ToolUseBlock without an id a generated one (toolu_mock_0001, ...).
  2. For tools defined with "strict": True, checks the scripted input against the schema (MockScriptError if it does not match).
  3. Applies stop_sequences: when the response would end with end_turn or tool_use and a text block contains a sequence, the text is cut before the earliest one, later blocks are dropped, stop_reason becomes "stop_sequence", and stop_sequence names the match.
  4. Applies max_tokens at about 4 characters per token: blocks that do not fit are cut (text) or dropped (tool use), and stop_reason becomes "max_tokens".
  5. When output_config.format is set and the response ended with end_turn, checks that the text parses as JSON and matches the schema (MockScriptError otherwise).
  6. Sets id (msg_mock_0002, ...; tool and message ids share one counter), model (the requested id), and usage (estimated input_tokens and output_tokens; cache counters stay 0).

messages.stream(**kwargs)

Same arguments as create. Returns a MessageStream to use as a context manager. The mock builds the whole response immediately and replays it as events, so a scripted failure or validation error is raised by the stream(...) call itself.

messages.count_tokens(**kwargs)

Takes model, messages, and optionally system and tools (max_tokens is optional here). The request is validated like create but nothing is generated, no step is consumed, and nothing is added to client.requests. Returns a MessageTokensCount whose input_tokens is the same estimate estimate_request_tokens gives.

Count steps carefully: one step answers one create or stream call. An agent loop that makes three requests needs three steps (or a responder).

def answer_from_result(request):
    weather = request.tool_results[0]["content"]          # what your code sent back
    return f"Here is the forecast: {weather}"

client = al.MockClient([al.tool_call("get_weather", {"city": "Paris"}), answer_from_result])
client = al.MockClient(responder=lambda request: f"echo: {request.last_user_text}")   # answers forever

stop_reason is one of "end_turn", "max_tokens", "stop_sequence", "tool_use", "pause_turn", "refusal". The mock produces all of them except pause_turn on its own; build a Message(content=[...], stop_reason="pause_turn") step to practice handling it. You can append response.content straight into messages: the mock converts blocks to dicts when it validates the next request, just as the SDK accepts its own block objects.

Streaming

with client.messages.stream(model=al.MODEL, max_tokens=512, messages=messages) as stream:
    for text in stream.text_stream:
        print(text, end="")
    final = stream.get_final_message()     # the complete Message
MessageStream memberMeaning
with ... as streamContext manager; returns itself.
for event in streamYields the remaining StreamEvents.
stream.text_streamYields only text fragments (from text_delta events).
stream.get_final_message()Consumes the rest and returns the Message.
stream.until_done()Consumes the rest.

Iteration, text_stream, and get_final_message share one underlying event iterator: events consumed by one are not seen by another.

Event sequence (each a StreamEvent with type, index, message, content_block, delta, usage):

  1. message_start: message is the response with empty content.
  2. For each block: content_block_start (content_block is an empty TextBlock, or a ToolUseBlock with input={}), then content_block_delta events (delta.type "text_delta" with delta.text, one per word; or "input_json_delta" with delta.partial_json, 16-character chunks of the input JSON), then content_block_stop.
  3. message_delta: delta.stop_reason, delta.stop_sequence, and usage.output_tokens.
  4. message_stop.

client.messages.create(..., stream=True) returns an iterator over the same events.

Validation rules

The mock checks each request before using the script. A rejected request raises immediately, is not recorded, and does not consume a step.

Script problems raise MockScriptError, which means the exercise or cell is wrong, not your agent: the script is used up with no responder; a scripted tool call names a tool when the request offered no tools; a strict tool's scripted input fails its schema; or output_config.format is set and the scripted reply is not matching JSON. (A scripted call to a tool name that is not offered, when other tools are, is allowed, so you can practice handling unknown tools.)

The live API: get_client

client = al.get_client(**options)   # anthropic.Anthropic(**options)

Returns a real anthropic.Anthropic client when the anthropic package is installed (locally, after pixi add anthropic). Credentials come from the environment (ANTHROPIC_API_KEY or an ant auth login profile); never pass a key in code. In the browser it raises LiveModelUnavailableError. A common local pattern:

import agentlab as al

try:
    client = al.get_client()
except al.LiveModelUnavailableError:
    client = al.MockClient(responder=lambda request: "mock answer: the real API is not available here")

Because the surface matches, moving code to the real API is one line. The only change below is how client is created:

import anthropic

client = anthropic.Anthropic()          # was: client = al.MockClient([...])
response = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Say hello in five words."}],
)
print(response.stop_reason, "".join(b.text for b in response.content if b.type == "text"))
