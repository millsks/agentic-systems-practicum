Roadmap: Levels 1-4

The practicum is eight stages in four levels, each level ending in a capstone. Level 1 takes you from your first API call to a tool-using research agent you can write from a blank file. Levels 2 to 4 take that agent to context management, evaluation, safety, shipping, and multi-agent systems. This page shows the whole path, what each stage covers, how long it takes, and the gate you should pass before moving on.

Hours are for a developer who already knows Python and does every exercise and mini-project. They include the capstone. Reading only is much faster; building is where the learning happens.

Everything in Level 1 runs in your browser against agentlab's scripted MockClient, with optional real-API mini-projects run locally through Pixi. Later levels will lean more on local projects and the real API, because evaluation, retrieval, and deployment need real model behavior. See M00 for how the course works.

Level 1 · Novice available

Outcome: you can write a tool-using agent from a blank file in under an hour and explain every line of its transcript.

Stage 1 · Talking to a model (10-11 h)

One request, one response. Everything an agent does is built from this call, so it pays to know it cold.

  • M01 What an LLM Call Is: tokens, context windows, why outputs vary, cost and latency
  • M02 The Messages API: roles, system prompts, content blocks, the response object, history as a list you own
  • M03 Limits, Effort & Stop Reasons: max_tokens, stop sequences, effort, every stop_reason
  • M04 Streaming: messages.stream, stream events, get_final_message
  • M05 Structured Output: JSON Schema, output_config.format, validating and recovering
  • M06 Prompting That Holds Up: clear instructions, examples, XML-tagged inputs, prompts as tested code

Stage 2 · Tool use and the agent loop (11-12 h)

Give the model tools, run its calls, and loop until it is done: the small loop at the heart of every agent framework.

  • M07 Tools as Contracts: names, descriptions, input schemas, strict tools
  • M08 One Tool Call by Hand: tool_use to tool_result, by hand
  • M09 The Agent Loop: stop reasons as control flow, parallel calls, a complete agent
  • M10 Errors as Data: is_error results, validating input, retry versus fix
  • M11 Stop Conditions & Budgets: step, token, cost, and time limits; loop detection
  • M12 Tool Design: fewer, clearer tools; readable results; testing tools alone

Capstone 1 · Research agent (5-7 h)

Build a research agent that searches, reads sources, and writes a cited answer, graded against a scripted model with pixi run grade c1.

Gate 1: ready for Level 2?

Before moving on, you should be able to do all of these without looking anything up:

  • Write a request with model, max_tokens, system, and multi-turn messages, and explain each field
  • Handle every stop_reason, including max_tokens and refusal
  • Define a strict tool and explain why additionalProperties: false is required
  • Write the agent loop from memory, including parallel tool_results in one user message
  • Turn tool failures into is_error results, and tell a 400 from a retryable error
  • Stop a run on steps, tokens, or cost, and return a structured report
  • Pass all of Capstone 1's graded checks

Level 2 · Practitioner planned

Outcome: you can keep an agent inside a context budget, choose between a workflow and an agent, and prove a change made things better with an evaluation suite.

Stage 3 · Context and memory (8-10 h)

  • The context budget: what fills the window over a long run, and measuring it
  • Compaction: summarizing and dropping old turns without losing the thread
  • Retrieval as a tool: search over documents the agent calls, rather than stuffing everything into the prompt
  • Files as memory: notes the agent writes and reads back across steps and sessions
  • Prompt caching: reusing a stable prefix to cut cost and latency
  • Lab: a docs Q&A agent that must answer within a fixed token budget

Stage 4 · Workflows vs agents (8-10 h)

  • Prompt chaining: fixed sequences of calls with checks between them
  • Routing: classify first, then send to a specialized prompt or model
  • Parallelization: sectioning and voting
  • Orchestrator-workers: one model plans, others execute
  • Evaluator-optimizer: generate, critique, revise
  • When an agent is the wrong choice, and a plain workflow or a single call is better

Stage 5 · Evaluation (8-10 h)

  • Test sets: collecting realistic cases, including the hard ones
  • Graders: exact match, code checks, and rubrics
  • Model-as-judge: using a model to grade, and checking the judge
  • Trajectory evaluation: grading the path (tool calls, steps), not only the final answer
  • Evals in CI: running the suite on every change
  • Error analysis: reading failures and turning them into fixes

Capstone 2 · Retrieval agent with an eval suite (10-12 h)

A retrieval agent over a document set, shipped with a 30-case evaluation suite that runs in CI and a written error analysis of its failures.

Gate 2: ready for Level 3?

  • Keep a long-running agent inside a token budget using compaction or retrieval
  • Explain, for a given task, whether a workflow or an agent fits better, and why
  • Build an eval suite with at least two kinds of grader, and run it in CI
  • Show with numbers that a prompt or tool change improved results
  • Pass Capstone 2

Level 3 · Production planned

Outcome: you can run an agent where mistakes cost money or data, observe it, and ship it as a service other systems can call.

Stage 6 · Reliability and safety (8-10 h)

  • Prompt injection: untrusted text in tool results that tries to take control, and defenses
  • Sandboxing: running tools with the least access they need
  • Permissions: which tools an agent may call, on whose behalf
  • Human in the loop: approvals that are fast enough to be used
  • Budgets and kill switches: hard limits that stop a run from outside
  • Idempotent tools: safe retries and exactly-once side effects

Stage 7 · Shipping agents (8-10 h)

  • Tracing with structlog: a structured record of every step, tool call, and token
  • Retries and rate limits: backoff, jitter, and concurrency control
  • MCP servers: exposing tools over the Model Context Protocol
  • SDKs: the Anthropic SDK's tool runner, and the Claude Agent SDK
  • Cost engineering: model choice, effort, caching, and batching
  • Deployment: packaging, configuration, secrets, and monitoring

Capstone 3 · MCP server plus hardened agent (12-15 h)

An MCP server exposing a small set of well-designed tools, and an agent that uses it with permissions, approvals, budgets, tracing, and an injection test suite.

Gate 3: ready for Level 4?

  • Demonstrate a prompt injection against a naive agent, then block it
  • Gate every write tool and show the audit trail of approvals
  • Trace a run end to end and find its most expensive step
  • Serve tools over MCP and call them from an agent
  • Pass Capstone 3

Level 4 · Professional planned

Outcome: you can design, build, and judge complex agent systems, and keep up as the field moves.

Stage 8 · Advanced agent systems (10-14 h)

  • Multi-agent systems: when several agents beat one, and when they do not
  • Subagents: delegating a scoped task with its own context
  • Long-running agents: checkpoints, resumption, and progress tracking
  • Coding agents: reading a repository, editing files, running tests
  • Computer use: agents that operate a screen
  • Designing a harness: the loop, tools, context, and guardrails as one system
  • Staying current: reading release notes and migrating deliberately

Capstone 4 · Coding agent (15-20 h)

A coding agent that takes a repository with a failing test, finds the cause, makes a fix, and proves it by running the test suite, inside a sandbox with budgets and an evaluation suite of its own.
